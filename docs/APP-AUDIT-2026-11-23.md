## 3. Bugs fixed

| # | Where | Problem | Fix |
|---|-------|---------|-----|
| 1 | `web/assets/store.js` | Every Settings toggle wrote preferences only, but `settings_set` replaces the whole document: all saved queues were lost at the next launch. | One writer carries preferences and queues together. |
| 2 | `web/app.js` | First-launch browser dialog called `saveSettings` before it was initialised (ReferenceError), and then wrote preferences only. | Uses `setPrefs({ browserSetupSeen })`. |
| 3 | `store.js` + new `queue-plan.js` | A download paused by hand inside an active queue was silently restarted on the next completion event or the next app start. | Per-queue `held` list; the orchestrator only advances rows waiting because of the queue. |
| 4 | `ui.js`, `screens/queues.js` | Assigning a download to a running queue did nothing until some other event fired. | The orchestrator is kicked on assignment. |
| 5 | `app/src-tauri/src/main.rs` + new `engine-core/src/paths.rs` | "Open file" / "Open folder" handed `explorer.exe` a verbatim `\\?\C:\...` path, which the shell does not accept: nothing opened on Windows. | The verbatim prefix is stripped for the shell launch only (validation unchanged). |
| 6 | `screens/downloads.js` | Changing the sort or filter had no visible effect, and new downloads always landed at the bottom of the list. | Rows are re-sequenced when the visible order changes. |
| 7 | `screens/downloads.js` | Every progress tick rebuilt the DOM of every visible row and of the filter buttons (keyboard focus was dropped). | Only rows whose data changed are repainted; counts are patched in place. |
| 8 | Row button, context menu, Space key, selection bar | Pause was offered for rows that are merging; the engine refuses that. | Pause is offered only for pausable states. |
| 9 | "Pause all" / "Resume paused" | "Resume paused" also restarted failed and cancelled downloads; "Pause all" skipped queued rows. | Each button does exactly its name. |
| 10 | `ui.js` confirm dialog | Escape or a click on the backdrop never settled the caller's `await`. | The dialog settles exactly once, whichever way it closes. |
| 11 | `events.rs`, `manager.rs`, `engine-bridge`, `store.js` | The first checksum of a file (no reference hash) was reported as "Verification passed". | The event carries `matches`; the UI says the checksum was stored with nothing to compare against yet. |
| 12 | `updater.js` | No guard against two installs; a background check could overwrite the "installing" state; a failed install left the paused downloads paused; merging rows were promised a seamless resume. | Re-entrancy guard, resume on failure, honest wording for merges. |
| 13 | `screens/settings.js` | "Browser extension — not implemented" although the extension ships with the installer. | Accurate text and a button that opens the Browser screen. |
| 14 | `manager.rs` | A stray run of spaces inside the "file is missing from disk" error. | Cleaned. |
| 15 | CI and docs | Frontend unit tests never ran in CI; `scripts/ci-local.sh` failed on Node 22+; README commands used wrong paths; the Windows `desktop` job ran from the wrong directory. | Fixed (YAML parse-checked only; not executed on GitHub). |

## 4. Loose points and improvements, ranked (not fixed)

1. **The desktop app crate is never compiled on push.** The `desktop` job in
   `windows.yml` is manual-dispatch only, so a broken `main.rs` is noticed at release
   time at the earliest. Enable the job (or a `cargo check` job) on push.
2. **Update channel.** `latest.json` has no signature and the updater signing key is not
   in this workspace. Existing installs cannot update in-app until a signed manifest is
   published.
3. **Private key in the repository.** `scripts/velox-extension-key.pem`. Rotating it
   changes the extension ID.
4. **Synchronous Tauri commands on the main thread.** `extension_status` is polled every
   3 seconds by the Browser screen; `extension_setup` and `open_path` run there too.
   Make them async so disk and registry work cannot stall the UI.
5. **Shutdown asymmetry.** Queued rows are not paused on close, and an update install
   exits through `process.exit`, which skips the close handler. An ffmpeg child can be
   orphaned and the row returns as "merge interrupted" (the dialog now says so).
6. **Non-atomic settings write.** `settings_set` uses `std::fs::write`; a power loss
   during the write truncates preferences and queues. Write to a temp file and rename.
7. **Smaller items.** The engine state `resolving` is never assigned to a row; "Open
   file" is enabled for failed rows; the NSIS template hardcodes `/tmp/installer/`.
8. **Repository hygiene.** `.env`, `upload/*` and `scripts/watchdog.log` are tracked;
   483 MB of build artifacts sit in the history.
9. **Documentation debt.** Several docs contradict the code (for example
   "adaptive streams refused", "nothing bundled", done roadmap items, a stale
   `download-engine/README` and `PROGRESS-LOG`, `STATE.md` naming
   `installer-online-template.nsi`). `docs/KNOWN-ISSUES.md` #2 and #4 are outdated by
   the fixes above.
